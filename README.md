# トレーディングカード相場・仕入判断

GitHub Pagesで配信する静的サイトです。ポケモン・ワンピースのPSA10と、BOX・パックの成約履歴を閲覧できます。

## ローカル確認

リポジトリで `python3 -m http.server 8765 --bind 127.0.0.1` を実行し、`http://127.0.0.1:8765/` を開きます。Chart.jsとsql.jsはCDNから読み込みます。データベースと画像マップは同じ公開先の `data/` を参照します。

計算・判定のテスト：`node --test tests/*.cjs`（追加パッケージ不要）。

## 仕入判断

- 実際の仕入価格を入力した場合と、過去7日安値を使った参考試算を区別します。過去安値は現在の出品価格ではありません。
- 売値の前提 = 7日中央値と直近3日中央値（3件以上）の低い方。7日中央値だけでは下落の途中で遅れるためです（PSA10）。
- 売却手取 = 売値の前提 × (1 − 販売手数料率) − 販売送料 − その他販売費。
- 利益 = 売却手取 − 商品代金 − 仕入時費用。利益率は商品代金と仕入時費用の合計に対する割合です。
- 仕入上限は損益分岐点（売却手取 − 仕入時費用、円未満切り捨て）で、その商品代金で利益0円です。利益目標の設定には左右されません。最低利益額・率は、入力した仕入価格が「条件達成」かどうかの判定に使います。販売価格が5％・10％下がる場合も確認できます。
- 狙い値は上限の5％下（市場判定が「注意」の日は10％下、「仕入停止」の日は出しません）。過去の成約では、上限ちょうどで仕入れると通常時でも3〜5割が赤字でした。
- 手数料・送料は変更可能な試算用の初期値です。スニダンの販売手数料は会員ランクで7.0〜9.5％に変わり、初期値はレギュラーの9.5％です。契約や販売方法に適用される最新費用を取得する機能はありません。税金は計算に含みません。
- PSA10の仕入候補は、探す優先度が「優先して探す」「候補」で、仕入上限が予算内の商品です（下の「市場の概況・探す優先度」を参照）。市場判定が「仕入停止」の日は出ません。仕入価格を入力して利益・取得件数・鮮度・予算・中立以上の相場トレンドを満たした商品は含みます（過去安値での参考試算は数えません）。同名・同型番で異なる商品ページがある場合は仕様確認を優先し、候補から除きます。
- 件数は取得できた成約のみです。市場全体の取引量、成約確率、売却所要日数を示しません。信頼度は取得件数と鮮度による目安です。
- PSA10の7日・14日集計、期間の変動、成約額はデータ内の最新成約時刻を基準にします（収集は1日1回のため、閲覧時刻を基準にすると直近7日が最大1日ぶん短くなります）。データが古い場合は最終取引の鮮度判定と概況の警告で示します。PSA10チャートの期間は閲覧時点の日本時間を基準にします。PSA10の当日／前日比は両日に成約がある場合のみ計算します。移動平均は観測がある取引日の点数を使います。
- BOX・パックの利益計算は閲覧時点の7日成約中央値を使います。既存の日次一覧は明示したデータ収集基準日を使います。パックの出品最安値は数量の比較条件が不明なため非表示です。

PSA10の仕入条件はブラウザのlocalStorageに保存します。入力した商品代金はページ内メモリのみで、再読み込み時に消えます。サーバーへの入力送信はありません。

## 公開

既存のGitHub Pages設定は `main` ブランチのルートです。HTML・`assets/` の変更を反映するとPagesが再構築します。データ収集処理自体はこの改修の対象外です。

## 画面構成

- 検索・商品一覧を優先し、チャートとデータの説明は一覧の後に配置しています。
- 利益計算はPCでは右側のパネル、スマートフォンではモーダルの下部シートで開きます。一覧のスクロール位置と入力値を保持し、Escapeまたは閉じるボタンで一覧へ戻れます。
- 仕入条件は利益目標・販売費用・候補条件に分けています。梱包費と仕入時費用は追加設定から変更できます。
- BOX・パックはPCの表とスマートフォンのカード表示を切り替えます。日次一覧の集計基準日と7日試算の違いは従来どおり明示しています。

## グラフ・リンク・並び替え

カードごとの「グラフ」から7日・14日・30日・全期間の成約価格と移動平均を表示します。一覧の小さなグラフは、直近30日の日別平均成約価格を商品ごとに縦軸を調整して描きます。2日分未満の場合は推移データ不足と表示します。「スニダン」はその商品のページを新しいタブで開きます。「メルカリ」「Yahoo!フリマ」「ヤフオク」は商品名（PSA10はカード名・型番・PSA10）で検索した結果を新しいタブで開きます。

並び替えは一覧上部から探す優先度、期間の変動・成約額、利益額・率、仕入上限、中央値・安値・高値、取得件数、トレンド、前日比・週比、最終取引日時、ランク、カード名を選択し、昇順・降順を切り替えます。PCでは表見出しのボタンでも変更できます。欠損値は両方向とも末尾です。利益額・率は入力済みなら入力価格、未入力なら過去安値による参考試算です（一覧には入力済みの利益だけを表示します）。初期の並びは探す優先度の高い順です。

## 市場の概況・探す優先度（PSA10）

ポケモン・ワンピースのPSA10ページ上部に、期間（1日・7日・30日・90日）を切り替えられる概況を置いています。選んだ期間は一覧の変動・成約額の列、候補、ヒートマップに共通で、このブラウザに保存します。

- 期間の変動：直近の成約の中央値と、その期間だけ前の成約の中央値の比較です。1日は24時間どうし、7日・30日・90日は7日間どうしを比べます。どちらかの成約が2件未満、または収集開始より前にかかる場合は「集計中」とし、0％とは扱いません。
- 成約額：取得できた成約価格の合計です。取引の多い商品は1日あたりの取得数に上限があるため、実際より小さくなります。
- ヒートマップ：面積が期間の成約額、色が期間の変動です。マスを押すとその商品の利益計算を開きます。
- 市場判定：7日変動を出せた商品（7日5件以上）の変動の中央値と、3％を超えて上げた・下げた商品の割合で決めます。中央値が−3％以下、または下げた商品が50％以上で「仕入停止」。中央値が−1％以下、または下げた割合が上げた割合より10ポイント以上多いと「注意」。それ以外は「通常」。比べられる商品が20未満なら「集計中」です。
- いま探す候補：探す優先度・値上がり・値下がり・成約額の上位8商品です。探す優先度の並びは、区分（優先して探す→候補）の順、同じ区分の中は成約件数の前週比が大きい順です。
- 探す優先度：過去の成約で下落が多かった4つの状態に当たらないかを見ます。①過熱（7日50件以上、またはランキング20位以内）、②値動き（7日変動が−8％以下、または+15％以上。前週と比べられない場合も含む）、③直近3日（直近3日の中央値が7日中央値より4％以上安い）、④成約件数（前週の半分以下）。どれにも当たらない商品が「候補」、そのうち成約件数が前週の1.25倍以上なら「優先して探す」。1つ当たると「様子見」、2つ以上で「見送り」。市場判定が「仕入停止」の日は、条件を満たしていても「様子見」止まりです。取得件数・鮮度・商品仕様の条件を満たさない商品は集計中です。
- 根拠：2026年7月18日〜11月17日のポケモンPSA10成約（約13.8万件）で、その日の売値の前提に対し3〜14日後の成約中央値がどうなったかを調べました。「仕入停止」に当たる日は、条件に関係なく約3割の商品が10％以上下げています。それ以外の日は、上の4つに当たらない商品の10％以上の下落が約5〜10％、当たる商品は約13〜23％でした。相場の向きの強さ・価格の安定・レアリティ・価格帯は、市場全体の動きを引くと差が出なかったため使っていません。
- 限界：データは4か月で、下落と反発が1回ずつです。しきい値は同じデータから決めています。市場判定は遅れて出るため、下落の初動と底打ちは拾えません。ワンピースの成約では4条件の向きは同じでしたが、「仕入停止」でない日が少なく、市場判定は十分に確かめられていません。
- スニダン内の成約だけを見ており、他の販路で上限以下で買える確率は測っていません。探す優先度は今後の値動きを保証するものではありません。
- 商品詳細で仕入価格を入力すると、直近30日の成約のうちその価格以下で成立した割合を表示します。

## 仕入おすすめ度（PSA10）

商品詳細に5段階と判定理由を表示し、おすすめ度でも並び替えできます。1＝利益なし・予算超過、2＝利益あり・下落、3＝利益あり・目標未達、4＝目標達成・中立以上、5＝4の条件に加えて入力価格あり・上昇・信頼度高です。未入力時は過去安値による参考評価（最大4）。取得件数・鮮度・商品仕様の確認条件を満たさない場合やトレンド不明は判定保留です。費用・目標・入力価格を変更すると再評価します。

相場トレンドの並び順は、降順が強い上昇→上昇→中立→下落→強い下落、昇順はその逆です。画面の判定と同じ基準で並び替え、判定保留は両方向とも末尾に置きます。
